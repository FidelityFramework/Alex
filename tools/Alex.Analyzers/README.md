# Alex analyzer tooling

Alex hosts these development-only F# analyzers inside `tools/Alex.Analyzers/`, isolated from `src/Alex/Alex.fsproj`'s production dependency boundary. For Alex work, run the required combined gate from the Alex repository root:

```sh
bash tools/Alex.Analyzers/analyze-alex.sh
```

The command uses Bozzetto's renewing lease client (`${BOZZETTO_DIR:-$repo_dir/../Bozzetto}/tools/build/lease.fsx`) for builds, truth controls and analysis. It runs the Alex boundary check first, then the required combined shared and Alex check. A boundary-only pass is a narrowed result; a combined failure remains a failure. The tool truth suite is an ordinary pipeline step, not a TRUST tier.

AXA001 detects construction of the published `Revision` and `SemanticNode` records. AXA002 detects the scoped nominal-name admission pattern in the `ensure` predicate, directly or through immutable local binding chains, resolved FSharp.Core boolean `not`, and the receiver and arguments of resolved `System.String.StartsWith`; it refuses when such a chain passes through a mutable local or cannot be inspected. Other methods are not admitted by a general method rule, and user-defined `not` functions and other calls remain boundaries. The analyzer also refuses when the referenced PSG contract lacks its target records or name field. Other method-call predicates, module-name checks, destructured names, module values, other guards, helper calls, local functions and piped helper values remain outside that rule; the truth receipt labels known misses. Admission based on values looked up by nominal name remains a policy question.

The shared baseline currently detects null, selected .NET APIs and imports, task builders, authored `box` references, intrinsic `obj` declarations and selected implicit widening. It follows non-FSharp.Core type abbreviations, including structural components, to detect aliases of `obj` or selected .NET types; it keeps FSharp.Core abbreviation heads intact and refuses type shapes it cannot resolve. The status of FSharp.Core `ResizeArray`, `Lazy`, `seq`, `exn`, `bigint` and `decimal` remains a policy question. The full dependency boundary is not established: unrelated foreign assemblies and several implicit widening shapes, including annotated bindings and returns, tuples, branches and multi-argument calls, remain open. Ordinary interpolated strings consumed as strings have a positive control; a direct interpolated-string-to-`obj` argument has a negative control. Absence of findings is not proof that these gaps are absent.

The combined Alex mode also checks the evaluated project dependency closure against the owner's permitted projects and packages. It compares the current NuGet restore graph with assets and binds resolved project, package and framework files to their recorded owners. The required wrapper runs the check under a lease; preprocess digests bracket the evaluations and analyzer, and the manifest records the inputs read. The sequence is not atomic and does not prevent concurrent source edits; MSBuild can update its assembly-reference cache. The analyzer loader's own resolved references are not yet compared with the validated set. Multi-target project references are refused. The selected framework pack must match the executing SDK's designation; other SDK items and properties are recorded through static preprocess evidence rather than independently validated. The check does not prove extracted package DLL bytes match the recorded package content hash. General `clef` mode is suspended until an owner convention supplies its permitted dependency sets (P-dep4); `alex-boundary` remains a narrowed analyzer observation.

Run `bash tests/run.sh --pipeline` only after building the fixtures and running `bash tests/project-control.sh`; the wrapper and pipeline do this in the required order. Truth receipts bind the analyzer, project input and coverage verifiers, fixtures and tooling configuration. The current combined gate is red and must be adjudicated from its actual diagnostics, without treating their count as a count of confirmed defects.

The dependency check disables MSBuild auto-response files and records that setting. Its bounded profile is Debug/AnyCPU with Microsoft.NETCore.App as the only admitted framework; additional permitted projects are refused. ResolveReferences runs under the wrapper's lease and may build referenced projects and update their outputs. The validator's PATH-resolved utilities remain trusted host inputs.
